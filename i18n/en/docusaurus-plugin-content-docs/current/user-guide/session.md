# Session

## Who This Is For

This page is for users who need to create, open, switch, or monitor Sessions.

## What It Is

A Session is the context for continuous work. It retains current messages, Task state, visible capabilities, uploaded attachments, Workspace artifacts, and execution notices.

## When to Use It

Keep each goal, project, file set, or problem in an appropriate Session. Do not mix unrelated work in the same Session.

## Basic Usage

Recommendations:

1. Open an existing Session from the Sessions page, or begin in the primary Session.
2. Give the Session a name that identifies its goal.
3. Continue adding material, approving Tool calls, and asking follow-up questions in the same Session.
4. Keep files and artifacts for the same project under the current Session's Workspace path.
5. When the goal changes substantially, create a new Session or switch to a more appropriate one.

Watch these areas on the Session page:

- The current response and message history.
- Running state, approval requests, and failure notices.
- Uploaded attachments and processing state.
- Generated files, reports, and previewable artifacts.
- Available Tools, Skills, Secrets, and model configuration.
