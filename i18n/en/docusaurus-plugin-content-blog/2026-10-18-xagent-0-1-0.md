xAgent `0.1.0` is a formal release focused on everyday work in a multi-user agent portal: organizing teams, resuming interrupted work, and keeping authentication and secrets within defined boundaries.

This article follows the [official release notes](https://github.com/coffeehc/xagent-releases/releases/tag/v0.1.0), including their October 18, 2026 release date. The free binary is intended for deployment trials and evaluation; check the version actually installed before following an operation.

## Virtual teams give collaboration a defined home

Version 0.1.0 supports virtual teams with a dedicated manager, member Session trees, reusable roles, manager delegation, and owner guidance. Team materials live in a shared directory to support a common business goal.

One possible use is a manager splitting a research task among members and bringing their results together. This is a usage example, not a claim that configuration, authorization, or acceptance happens automatically. See the [virtual teams guide](/docs/user-guide/virtual-teams) for the boundaries.

Dissolving a team archives it as a whole while retaining member relationships. Archive pagination and read-only inspection improve, and long-idle Sessions can be archived automatically. Restoration and continued execution use explicit entry points; retained materials do not mean a task is still running.

## Better continuity after interruptions

The release unifies Session input batches and runtime-state recovery, improving interrupted team dispatch, collaboration replay, and message continuation. The MCP SDK upgrade strengthens connection reuse, cancellation, and stale-connection recovery, alongside HTTP first-byte waiting and streaming-response handling.

These changes support continuity. Completion still requires checking actual deliverables, external effects, and acceptance criteria, rather than relying on a reply or a recovered status indicator.

## A consistent Session and administration interface

The site adopts XUI 4.2.18 with a forest-green palette and consistent lists, tables, cards, forms, and overlays. Session indexes, elapsed time, tool calls, task progress, and approval prompts improve; Session and administration sidebars receive separate width adjustments.

Initial on-demand loading, compressed static assets, structured-memory details, and exception-record management are also improved. Approval-policy edits save immediately: check their scope before editing and verify the result afterward.

## Authentication and secrets retain execution boundaries

Web and desktop use a unified Cookie Session flow with improved initialization, logout, and new-document loading. Secret placeholders resolve only at permitted request-execution boundaries; files, messages, and persisted content retain placeholders instead of expanded secrets.

This does not authorize sending credentials to arbitrary destinations. Check task authorization, request destinations, and approval rules, and keep real secrets out of prompts, Workspace files, and screenshots.

## Installation, upgrades, and verification scope

Binary packages cover Linux and macOS on AMD64 and ARM64. See [installation](/docs/getting-started/install) for the procedure and the [changelog](/docs/changelog) for a summary. Back up configuration, databases, Workspaces, Memory, Skill and Tool packages, and AgentPlugin configuration and state before upgrading.

Only Server 0.1.0 is released here; independent AgentPlugins, desktop clients, and runtime assets keep their own versions. The release page provides platform packages, checksums, release metadata, and license files. Verify downloaded packages against its SHA-256 instructions.

The official notes explicitly state that the full test suite was not rerun. Four-platform builds, package and binary checksums, installer mock checks, and public-download integrity are not full business acceptance on all four platforms. After upgrading, use non-sensitive material to verify Sessions, team collaboration, and the external connections you need.
