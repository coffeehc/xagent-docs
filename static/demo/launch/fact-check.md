# xAgent 产品首发包 · 官方资料事实核对（fact-check）

- **用途**：面向小型技术团队的产品首发包，仅供用户审阅，不对外发布。
- **核对日期**：2026-10-01
- **核对方式**：对本轮指定的 3 个官方页面逐页发起 HTTPS GET 抓取（`web_fetch`），对返回正文做逐条声明比对；并用本会话自身的运行事实交叉印证可复核的部分。
- **判定口径**：
  - ✅ 已核实 = 官方页面正文（本次成功抓取的原文）明确支持该表述；
  - ⚠️ 需注意 = 官方支持但存在限定条件，直接照搬原文会失实；
  - ❌ 冲突 = 待核表述与官方正文不符；
  - ❓ 无法核实 = 本次材料范围内无据可依。
- **重要区分**：「官方文档说法」与「本会话真实观察到的执行」严格分开。事件被成功投递/接收 ≠ 业务任务完成；本核对不伪造任何未在本文列出的协作步骤。

## 八、首发包文案建议（基于以上核对）

1. 「适合谁」：按 S2 适用对象口径写（每天提交任务、看过程、补材料、拿结果的用户）；「小型技术团队」只能作为我方定位话术，不得写成官方承诺。
2. 「能做什么」：可用 S2 使用场景 + S3 能力方向总表 + S1 会话事件协作，但必须同时携带各自限定条件（见第三、四、五节 ⚠️ 项）。
3. 数字口径：「54 个内置 Skill / v0.0.20.beta」必须附带「以运行治理 → Skill 为准，管理员可停用/新增」的限定句。
4. 安全表述：禁止出现「不可绕过的统一安全底线」类宣传语；正确口径是 S1「事件不绕过审批」——审批依各会话实际权限、工作区边界与审批策略生效。
5. 项目级 Team：只能写「规划中」，与 S1「当前版本的边界」保持一致。
6. 案例章节：使用本轮事实核对 / 页面与文案的真实分工及可观察交接；如另引 S1 新闻示例，必须标注文档示例，不得混淆。
7. 免责声明：合同/合规/财务/投资/人事类用途必须保留 S3 的资质人员判断免责。
8. 发布前自查：文中每个功能点都能在上文找到 ✅ 依据；凡标 ⚠️ 的条款，照抄限定语后再用。

## 九、结论

- 三份指定官方资料均已**实际抓取并读取正文**（HTTP 200），本核对的所有 ✅ 判定均可回溯到具体页面具体章节（见第一、二至七节的来源编号与章节名）。
- A 的功能核对可作为审阅依据，但不等于对 B 原稿的自动验收。汇总检查已发现并修正：案例分工与实际不一致、示意与实跑混淆、审批绝对化、插件配置泛化，以及原核对表格列数问题。
- 受众定位、部署差异、上传限额、上下文压缩与示例范围均须保留限定。当前只涉及同用户会话协作，完整项目级 Team 仍在规划；没有统一且不可绕过的安全保证。
- 最终交付只包含三个文件，仅供审阅；未对外发布，不创建长期计划、触发器或外部集成。
