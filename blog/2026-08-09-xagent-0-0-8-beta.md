xAgent `0.0.8.beta` 已发布。本版本把存储治理从“文件放在哪里”继续推进到“数据如何备份、故障后如何恢复、外部存储如何接入”，并补齐会话复用文件、Skill 多语言治理和本地存储清理。

如果只看一个变化，建议先看在线增量备份：备份任务可以在 xAgent 运行时完成，恢复数据也可以先在线下载和校验，只有最后切换数据目录时需要停机。

## 在线增量备份与灾难恢复

管理员现在可以把 S3、兼容 S3 的对象存储或 WebDAV 配置为备份仓库，并在启用前测试连接、初始化仓库。备份可以手动触发，也可以使用 Cron 表达式和 IANA 时区定时执行，同时设置完整快照的保留数量。

从恢复视角看，每个完成的快照都对应一份完整数据目录；从远端存储视角看，xAgent 使用内容寻址，只上传新增或变化的对象。数据离开本机前会先加密，因此不需要在“每次传完整副本”和“降低远端占用”之间二选一。

恢复分为两个阶段：先在线下载、校验并重组指定或最新快照，再停止 xAgent 执行目录切换。切换后先启动服务验证；确认正常再清理回滚副本，验证失败则停机回滚。备份仓库初始化后还可以下载独立的 `recovery.yml`，原数据库不可用时也能列出快照并准备恢复。

完整操作步骤、命令和恢复边界见[《xAgent 在线备份与灾难恢复：从增量快照到 recovery.yml》](/blog/xagent-backup-and-disaster-recovery)。

## S3 与 WebDAV 进入公共目录

S3、兼容 S3 和 WebDAV 现在作为云存储接入映射到公共目录。每个接入使用独立前缀；管理员可以创建目录和上传文件，获得授权的用户可以浏览、预览和下载内容，原有按用户或用户组配置的公共目录 ACL 继续生效。

接入配置支持 S3 默认凭据链、静态凭据、path-style 地址以及 WebDAV 用户名和密码。静态凭据会加密保存。内部自签名存储可以单独开启“跳过 TLS 证书校验”，但该选项只应在确认网络边界和证书来源后使用。

当远端暂时不可用时，目录入口会保留并明确显示不可用，不会被误认为空目录。

## 会话直接复用现有文件

消息输入区新增工作区文件入口，可以把当前可见的工作区、公共目录或云存储文件直接作为会话附件，不必先下载到本地再重新上传。

这条路径与本地上传使用相同的文件类型、大小、模型能力和会话状态校验。导入失败不会留下无效附件。对于公共目录中的远端文件，xAgent 会在任务需要时处理成模型可读内容，原文件仍保留在 S3 或 WebDAV。

## Skill、Connector 与生产能力治理

Skill 列表、搜索结果和运行时能力会按照当前回复语言投影；英文环境新增英文 Skill 创建能力。Skill 的正式名称统一来自 `SKILL.md`，列表、会话和运行时不再出现不同名称。

Connector 卡片现在使用服务声明的真实版本，并校验关联 Skill ID。生产模式下，开发期专用的 Tool 管理页面和修改接口会被隐藏，但会话与智能体的 Tool 选择、审批策略和个人 MCP 不受影响。

## 本地存储清理

后台清理现在同时观察磁盘空间和 inode 使用率。达到普通水位时按保留期清理，达到高水位时会更积极地回收过期的备份暂存、终态诊断、会话临时文件、失败的 Runtime Assets 暂存和未被引用的文件内容。

清理边界保持严格：正式用户数据不会因为“文件较旧”被删除；活跃任务、待处理队列、正在投递的事件和仍被引用的文件也不在回收范围内。不同数据所有者的清理任务相互隔离，一个任务失败不会阻断其他任务，后续会再次尝试。

## 从 0.0.7.beta 升级

`0.0.8.beta` 起，xAgent 的正式文件存储固定回到本地目录。旧版本如果把正式文件存储放在 S3，升级时会先验证旧目录的归属和完整性，再把正式对象迁回本地；全部成功后才移除旧配置。远端不可访问或完整性校验失败时，启动会停止并保留原配置，避免带着不完整数据继续运行。

S3 和 WebDAV 在新版本中用于公共目录云存储接入，不再作为正式文件存储 Provider。升级前仍应备份配置、数据库、工作区、Memory、Skill、Tool 包和 Connector 状态。

备份仓库初始化后，请立即下载并离线保存最新 `recovery.yml`。它包含访问仓库和解密备份所需的敏感信息，不应放入代码仓库、聊天附件或普通共享目录。公共目录背后的第三方云存储内容不进入 xAgent 备份，应由对应存储服务单独设置版本、复制或备份策略。

安装与升级步骤见[开始安装](/docs/getting-started/install)，版本摘要见[更新日志](/docs/changelog)。
