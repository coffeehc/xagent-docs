# 虚拟团队：经理、成员与归档

版本范围：下述团队能力自 Server `v0.1.0` 引入，依据[正式发布说明](https://github.com/coffeehc/xagent-releases/releases/tag/v0.1.0)。10 月 23 日实测与首次任务练习是独立证据，下文分别链接。请核对自己的安装版本；本页更新不表示所有团队操作都已在 `v0.1.1` 重新测试。手册其他位置的旧截图可能展示较早界面。

## 什么时候使用 Agent Teams {/* #when-to-use-a-team */}

一个目标需要明确分工与可检查的交接时，可以使用团队，例如提取给定事实、编辑短说明、核对结果。一个人也可以拥有一个 Agent 团队。单个会话能处理的短文本改写或简单问答，不必为了使用团队而拆分。

先选输入和验收标准清楚的小任务。成员的独立上下文有助于分开职责，但交接也会增加协调工作，不能假定成员越多就越快或越省钱。[Agent Teams 实测](/blog/xagent-agent-teams-field-test)观察到的是研究后再编辑，没有验证并行加速。

## 先完成一次团队任务 {/* #first-team-task */}

已有获得授权的实例，可直接跟着[给定事实转短文练习](/docs/getting-started/first-task#first-success-agent-team-brief)开始。教程提供三条事实、完整任务、费用与容量检查及验收标准，无需上传文件、联网搜索或连接外部账号。没有实例时，请管理员完成[安装与初始化](/docs/getting-started/install)。

这是独立练习，不是公开实测的回放或成功保证。可用模型、容量、权限和实际执行结果仍取决于自己的实例。

## 开始一个团队 {/* #start-team */}

1. 创建虚拟团队，初始化专用经理。
2. 向经理说明目标、材料、边界和验收标准；按需复用岗位模板，并查看成员会话树。
3. 跟进成员聊天和任务结果；需要澄清或决策时，使用所有者指导入口。经理可以委托其他经理，但委托成功不等于任务完成。
4. 到共享业务目录核对成果，查看文件引用与预览，再按验收标准确认结果。

团队资料共享不等于授权访问其他用户或外部系统；原有账号权限和审批规则仍适用。WorkGroup 编排配置、会话执行和远端 A2A 是不同层次。

## 检查交接与结果 {/* #check-the-result */}

验收前分别核对三层事实：

1. **配置：** 经理和预期成员可见。“已就绪”只说明团队状态，不能当作任务完成。
2. **执行：** 打开每个成员会话，检查实际收到的派工及对应回复。有先后依赖时，核对编辑使用了研究员的实际报告。
3. **结果：** 将经理最终答复与输入、成员回复逐项比较。文件任务要打开实际文件核对内容，不能只看文件名或附件引用；首次短文练习则检查会话中的文字回复。

记录停止、纠偏、失败和额外动作。[实测执行记录](/blog/xagent-agent-teams-field-test)包含等待引用失败、越界写文件、无效附件和人工纠偏。最终文字交付不能证明无人值守可靠性，也不能证明文件交付已通过。

## 卡住或偏离目标时 {/* #team-recovery */}

| 现象 | 检查或下一步 |
| --- | --- |
| 只有经理，或团队显示“已就绪” | 提交有边界的具体目标，检查成员实际派工；不要把配置完成当作执行成功。 |
| 没有具体目标，初始化却持续运行 | 终止当前执行，等待停止完成，再提交限定范围的任务。 |
| 无法招募成员或模型不能运行 | 检查团队与会话容量、账号权限、模型实际 Tool calling 表现；连接测试成功还不够。 |
| 等待引用或附件引用失败 | 先检查成员回报和当前状态，再决定如何继续。回执不明确时不要直接重复动作；打不开的文件不能算交付。 |
| 经理提出额外目标、文件操作或归档 | 发送明确的所有者指导或停止执行，再核对指导已进入会话，最终状态符合任务范围。 |

自然语言约束不能代替工具权限和[审批策略](/docs/user-guide/approval-policy)。自己的检查通过前，使用非敏感材料；在原团队恢复的方法见[首次任务教程](/docs/getting-started/first-task#recover-in-the-same-team)。

## 归档、恢复与继续执行 {/* #archive-restore */}

解散团队会整体归档并保留成员关系，归档资料可只读查看。恢复团队和继续执行有明确入口，不应把恢复当作自动续跑；继续前先核对原目标和未完成动作。

长期未使用的会话也可自动归档。会话从活跃列表消失时，按普通、团队、插件与已归档导航范围查找。发布说明没有给出统一闲置时长，请核对当前部署，不要假定固定阈值。

## 升级后验证 {/* #verify-upgrade */}

用非敏感测试材料依次检查创建团队、经理初始化、成员任务、共享产物、归档只读查看、恢复和明确续跑。以自己的部署验证为准；发布时的构建与完整性检查不等于完整业务验收。
