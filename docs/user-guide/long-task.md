# xAgent 长任务：持续执行与阶段性交付

> 状态：实验性能力，页面和字段可能变化。

## 适用对象 {/* #适用对象 */}

本文适合需要让 xAgent 处理多步骤、长时间或阶段性交付任务的用户。

## 这是什么 {/* #这是什么 */}

长任务是不能靠一次短回复稳定完成的任务。它可能需要读取大量材料、分阶段执行、等待确认、调用外部系统、生成多个文件，或在较长时间内持续跟进。

普通用户不需要知道内部如何拆分，只需要把目标、材料、阶段和验收要求说清楚。

xAgent 在服务端执行任务，不依赖浏览器或用户电脑持续在线。关闭页面后，已经提交的任务仍可以继续运行；任务是否能完成，还取决于模型、工具、外部系统、材料和审批状态。

当前版本根据完整输入与输出预留计算压缩触发线：常规软线为模型上下文窗口的 90%，输出预留较大时还会提前收紧。早期文档的固定 80% 说法不再适用于当前策略。压缩保存的是当前任务的目标、进度、约束、决定、关键事实和产物引用，用于继续执行，不等同于长期记忆，也不能保证保留所有历史细节。

## 什么时候使用 {/* #什么时候使用 */}

下面任务适合按长任务组织：

- 研究多个来源并生成报告。
- 分析大量文件或数据。
- 持续跟进客户、邮件或外部事件。
- 每天、每周重复生成固定产物。
- 需要先计划、再确认、再执行。
- 需要多个中间结果和最终交付物。

简单问答、短文本改写、单个文件小结通常不需要长任务方式。

复杂长任务中，主 Agent 可能会把部分工作拆给子 Agent。普通用户不需要手动管理子 Agent，只需要在原会话里查看阶段结果、补充材料和确认关键动作。

## 提交方式 {/* #提交方式 */}

建议长任务第一条消息包含：

| 内容 | 示例 |
| --- | --- |
| 最终目标 | 生成一份客户反馈分析报告 |
| 材料范围 | 使用我上传的 5 份访谈记录 |
| 阶段划分 | 先列计划，确认后再分析 |
| 中间结果 | 先输出主题分类和证据 |
| 最终交付 | 生成 HTML 报告 |
| 确认点 | 外发或删除前必须确认 |

示例：

```text
请基于我上传的 5 份访谈记录做用户需求分析。
先列处理计划，等我确认后再提取主题、证据和机会点。
最后生成一份 HTML 报告，并把原始证据保留在附录里。
```

## 推荐流程 {/* #推荐流程 */}

### 先让 xAgent 列计划 {/* #先让-xagent-列计划 */}

复杂任务建议先写：

```text
请先列出处理计划，不要立即执行。
```

确认计划后，再让 xAgent 继续。

### 分阶段验收 {/* #分阶段验收 */}

长任务不要只看最终结果。建议在每个阶段检查：

- 材料是否读取正确。
- 分类是否合理。
- 证据是否充分。
- 输出格式是否符合要求。
- 是否有需要补充的材料。

如果某阶段偏了，马上修正，避免最后返工。

### 保存关键产物 {/* #保存关键产物 */}

长任务容易产生多个结果。建议明确要求保存：

- 阶段计划。
- 数据清洗结果。
- 中间分析表。
- 最终报告。
- 证据清单。

示例：

```text
请把中间分析表保存为 CSV，最终报告保存为 HTML。
```

## 运行中处理 {/* #运行中处理 */}

| 状态 | 处理方式 |
| --- | --- |
| 等待补充材料 | 在原会话上传或说明 |
| 等待审批 | 看清楚动作后确认或拒绝 |
| 外部连接失败 | 检查连接状态或改为手动提供材料 |
| 中间结果不对 | 立即修正要求 |
| 任务太大 | 缩小范围或分阶段处理 |

不要重复创建多个相同长任务。优先在原会话继续推进。

服务重启后，xAgent 会尝试恢复具有有效运行快照的会话。等待审批的会话仍会保持等待，不会绕过确认自动继续。恢复能力不代表所有外部操作都能无损或精确续跑，外部服务是否具备幂等和重复执行保护仍由相应工具与服务决定。

## 连续性检查清单 {/* #连续性检查清单 */}

在阶段切换、压缩、重启或子会话回传后，先核对：

- 当前目标和尚未完成的验收要求。
- 工作记录的最新摘要、未覆盖增量和证据引用。
- 最终文件是否真实生成、可打开且内容正确。
- 外部动作是已提交、效果未知，还是已有可核对的完成回执。
- 下一步由哪个会话负责，是否缺少用户材料或审批。

工作记录为当前会话保存主题、修订和追加条目；上下文摘要帮助继续执行；长期记忆复用稳定背景。不要把三者当成同一种“自动记住全部历史”的能力。

定时任务还需要区分“本轮已结束”和“周期触发器仍启用”。`v0.0.22.beta` 中，未完成或正在等待的同一触发器业务轮会阻止下一轮启动；等待反馈不是失败，也不会仅因聊天回复结束就自动完成。等待 A2A 的任务要核对原远端行动，避免迟到回执被误当成新一轮的授权。

工作记录、周期任务等待与恢复能力见 [v0.0.22.beta 发布说明](https://github.com/coffeehc/xagent-releases/releases/tag/v0.0.22.beta)。周期状态的操作边界见 [触发器](/docs/user-guide/trigger#business-rounds)。

## 重启与外部结果的恢复检查 {/* #recovery-checks */}

恢复时先回到原会话，不要立即重建任务或重复发起外部动作：

1. 核对服务版本、原始任务消息、最后阶段结果、工作记录与文件。会话处于归档状态时，先判断是否确实需要恢复执行，见 [归档与恢复](/docs/user-guide/agent-session#archive-and-restore)。
2. 区分正在执行、等待材料、等待审批与失败。等待不是丢失任务；先解决原来的等待事项，不能以超时或重启代替审批。
3. 外部结果不明确时，先查询原请求或远端任务。保留原行动标识、计划时间和回执，避免把迟到结果当成新任务。
4. 只有确定缺失的步骤才考虑重试；涉及写入或外发，先核对目标系统是否已经生效，再沿原授权范围继续。
5. 用真实产物或目标系统回执验收，再确认本轮完成。仍无法定位时，记录版本、会话标识、发生时间和脱敏错误交给管理员排查，不提交凭据。

接收外部状态时，首条消息与会话状态变更在同一事务中持久化，服务重启后扫描状态并接续恢复；这不等于外部业务“恰好执行一次”。业务去重、幂等键和完成确认（ACK）需要工具及接入系统配合。A2A 的原任务查询、效果未知与迟到结果处理也不能替代目标系统的业务验收。

## 常见场景 {/* #常见场景 */}

### 周报 {/* #周报 */}

```text
请整理本周项目材料，先列出缺失信息，再生成周报草稿，最后保存为 Markdown。
```

### 调研报告 {/* #调研报告 */}

```text
请围绕这个主题做资料整理，先给来源清单和分析框架，确认后再生成完整报告。
```

### 客户跟进 {/* #客户跟进 */}

```text
请汇总最近一周客户消息，整理待回复事项、风险客户和建议动作，不要自动发送消息。
```
