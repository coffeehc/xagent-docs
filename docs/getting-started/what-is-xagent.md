# xAgent 产品介绍与核心能力

## 先用一句话说清楚

xAgent 更像一个**AI 门户和 AI 基座**：它为员工提供统一的 AI 使用入口，也让企业能够统一管理模型、能力、权限和使用过程。它把团队已经在用的系统连接起来，在用户已有的账号和权限范围内，帮助完成具体任务。

你可以让它拆解目标、制定计划、执行操作、复盘数据，并把不同系统里的信息和动作串起来。这样，原本分散的系统可以围绕同一项工作协同起来。

xAgent 不要求团队更换原有系统，也不会凭空扩大用户权限。它负责理解任务、组织执行和汇总结果；每个系统能访问什么，仍由该系统的账号和授权决定。

当前版本是 `v0.0.5.beta` 测试版，适合部署体验、场景验证和反馈。

## 为什么要用 xAgent

1. **不用给每个员工单独部署**：员工打开浏览器，或者直接在微信里发文字、语音，就可以提交任务，任务由服务端统一执行。
2. **统一接入，按原有权限使用**：管理员统一接入内部系统后，员工只需要扫码或使用账号登录对应系统完成身份确认，xAgent 就会按员工在该系统中的既有权限提供访问能力，不新增权限。
3. **重要资料集中在服务器上**：团队的任务材料和结果统一保存在服务端，减少在员工电脑上保存敏感资料、密码和中间文件，降低终端中毒、丢失或被盗带来的暴露风险。
4. **安全和方便之间取得平衡**：xAgent 不会让 AI 无限制地自主操作。发送消息、删除文件、修改数据等关键动作，可以要求用户审批确认；多一步确认，换来更清晰的控制边界。
5. **把复杂细节藏起来**：管理员负责模型、工具、连接和策略配置，普通用户通常只需要会打字、说清楚目标，就能开始使用。

## 它能帮你做什么

常见用法包括：

- 读合同、会议记录、PDF、表格和代码，提取重点、风险和待办事项。
- 做资料研究、数据分析、周报、方案、文章、客户回复和项目清单。
- 根据需求写简单的程序，阅读和修改代码，定位问题并运行测试验证结果。
- 把结果保存成 Markdown、Excel、CSV、HTML 报告或其他工作区文件。
- 通过浏览器、邮件、微信、Telegram、飞书或企业系统完成后续动作。
- 把一件复杂的工作拆成几个阶段，持续执行，等你补充材料或确认后再继续。

目前内置 Skill 和支持的文档格式，见[支持的智能体功能](/docs/manual/capabilities)。

## 它是怎么工作的

假设你说：“请把这三份销售表整理成一份周报，标出异常，先给我草稿，不要发送。”

1. xAgent 读取你提供的文件，理解目标和限制。
2. 它按需选择合适的 Skill 和 Tool，而不是一开始加载所有能力。
3. 它分析数据、生成周报，并把文件保存到工作区。
4. 因为你说了“不要发送”，它会停在草稿阶段，不会擅自发消息。
5. 你确认内容后，可以让它继续发送，或把这套流程保存成以后反复使用的能力。

## 它有什么特点

- **以任务为中心**：重点不是陪你聊多久，而是把目标推进到可以检查的结果。
- **能处理真实材料**：不只回答问题，还能读文件、生成文件、保存文件和继续修改。
- **能调用外部能力**：需要查网页、处理表格或联系外部系统时，可以按需调用对应工具。
- **能记住工作上下文**：同一会话里可以连续补充要求，也能把稳定流程沉淀给团队复用。
- **有人把关**：发送、删除、覆盖或修改外部数据等敏感动作，可以先停下来等待审批。
- **适合团队自建**：服务部署在自己的服务器上，工作区和模型服务可以放在自己的环境里。
- **工作经验可以沉淀**：一次任务完成后，员工可以对 AI 说“帮我把这个流程总结为 Skill”，xAgent 会协助整理、测试和优化；如果还需要固定角色、提示词和能力入口，也可以进一步生成一个专用智能体。

## 和普通聊天助手有什么不同

| 对比 | 普通聊天助手 | 单一专用机器人 | xAgent |
| --- | --- | --- | --- |
| 主要用途 | 回答问题、生成文字 | 解决一个固定场景 | 围绕任务组合多个工作能力 |
| 处理材料 | 多数停留在对话里 | 取决于具体产品 | 文件、表格、网页和会话资料都可以成为任务材料 |
| 做事方式 | 你问一句，它答一句 | 按预设流程运行 | 可以持续推进、分阶段执行，并根据任务补齐能力 |
| 能力扩展 | 依赖产品内置功能 | 通常需要重新开发 | 用 Skill、Tool、MCP 和 Connector 组合扩展 |
| 结果 | 主要是文本 | 固定场景的结果 | 回复、文件、报告和经过确认的外部动作 |
| 团队使用 | 个人使用为主 | 由开发者维护 | 管理员统一配置，用户直接复用 |

简单说：普通聊天助手更像“问答窗口”，单一机器人更像“固定机器”，xAgent 更像“可以不断装备新能力的团队工作台”。

## 它不负责什么

xAgent 负责理解任务、组织能力和控制执行边界，但不替代组织的账号体系、业务权限、备份和审计。外部系统能访问什么，仍由外部账号、Connector 或 MCP 的授权决定。

它运行在服务端，不需要每台电脑都安装客户端。长期稳定运行建议使用 Debian Linux；macOS 是 xAgent 的主要开发环境，支持也很好。Windows 当前沙箱能力不足，无法为受控脚本执行提供同等安全、可控的保障，因此暂不建议作为部署环境。

## 几个词，用大白话解释

| 名词 | 可以把它理解成 | 作用 |
| --- | --- | --- |
| Agent | 一个工作入口 | 例如“通用助手”“合同审查助手”“周报助手” |
| Skill | 一套做事方法 | 规定什么时候用、按什么步骤做、结果长什么样 |
| Tool / MCP | 一个具体动作或外部能力接口 | 读文件、写表格、抓网页、发邮件或连接外部系统 |
| Connector | 接入外部世界的入口 | 把微信、Telegram、飞书、浏览器或企业系统接进来 |
| Workspace | 工作资料柜 | 保存上传的材料、中间文件和最终结果 |

这些能力都由管理员统一配置，普通用户通常只需要说明目标和交付要求即可开始。
