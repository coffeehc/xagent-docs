# 什么是 xAgent

## 先用一句话说清楚 {/* #先用一句话说清楚 */}

xAgent 是一个**面向持续工作的 Agentic 平台**。你提出目标、提供材料和限制，Agent 通过规划、调用工具、检查结果和调整下一步，把多步骤任务推进到可以检查的交付物。

它把长任务、上下文工程、长期记忆、多智能体协作和工具连接放在同一个服务端平台中。工作可以分阶段推进，在需要补充信息或审批时等待，再根据已有状态继续；结果可以是分析结论、文档、代码，也可以是经授权的外部操作。

个人可以用它处理持续性工作，团队可以统一准备模型、Skills、工具和访问策略。多用户门户是使用入口，自托管是部署方式，持续推进任务才是产品的核心。

截至 2026-10-23，最新公开二进制发行版是 2026-10-23 发布的 `v0.1.1` 正式发行版，适合部署体验、场景验证和反馈。具体功能与限制仍应以实际部署版本为准。

## Agent Harness：模型之外的运行体系

Agentic 平台是产品定位，**Agent Harness** 是支撑 Agent 执行的运行体系：模型负责理解目标和决定下一步，模型之外的机制负责提供工具、组织上下文、保存进度、接续任务、协调子 Agent，并按配置引入人工审批和执行记录。它不只是提示词，也不等同于模型本身。

在 xAgent 中，可以用 Agent Harness 理解下面这些能力的组合：Tool Calling、Context Engineering、Agent Memory、Resumable Execution、Agent Teams / Multi-agent Orchestration、Multi-agent Collaboration、Human-in-the-loop 与 Observability。这里描述的是已有机制的职责分工，不代表符合某种统一认证标准，也不承诺任务必然完成。

概念背景可参考 Anthropic 的 [Effective harnesses for long-running agents](https://www.anthropic.com/research/effective-harnesses-for-long-running-agents)。该文讨论长任务跨上下文持续推进的工程实践；xAgent 的实现和效果仍需按自身文档与实际任务验证，不代表使用同一架构或获得官方背书。

## 为什么要用 xAgent {/* #为什么要用-xagent */}

1. **让多步骤工作接着做**：研究、分析、写作和修改可以围绕同一目标分阶段推进，不必把每个步骤都当成新的问答。
2. **在需要时补齐方法和工具**：Agent 按任务加载相关 Skills 和工具说明，让模型上下文优先留给当前材料、约束与执行结果。
3. **复用经过确认的背景和方法**：长期记忆用于跨会话保留稳定信息；Skills 用于复用任务方法，两者分别管理，不把所有聊天都当成长期知识。
4. **组织 Agent 团队分工协作**：通过专用经理、成员会话树、岗位模板和经理委托组织复杂任务；成员独立执行，再结合共享资料、回复和产物核对结果。
5. **保留人的检查与决策入口**：通过人工审批、任务状态和执行记录，检查正在做什么、哪些动作需要确认、最终交付是否满足要求。

## 它能帮你做什么 {/* #它能帮你做什么 */}

常见用法包括：

- 读取合同、会议记录、PDF、表格和代码，提取重点、风险和待办事项。
- 结合资料检索和工具调用，完成研究、数据分析、周报、方案、文章和项目清单。
- 根据需求编写或修改程序，定位问题，并运行测试验证结果。
- 将结果保存为 Word、PowerPoint、Excel、PDF、Markdown、CSV、HTML 报告或其他工作区文件。
- 通过已配置并授权的浏览器、邮件、微信、Telegram、飞书或企业系统完成后续动作。
- 持续修改交付物，在等待材料、用户确认或外部结果后继续工作。

这些任务的效果取决于模型、已加载的 Skills、可用工具和外部账号权限。内置 Skills 与支持的文档格式，见[支持的智能体功能](/docs/manual/capabilities)。

## 它是怎么工作的 {/* #它是怎么工作的 */}

假设你说：“请把这三份销售表整理成一份周报，标出异常，先给我草稿，不要发送。”

1. **理解目标与限制**：读取文件，明确报告范围、交付形式和“不要发送”的要求。
2. **规划并选择能力**：按需加载数据分析相关的 Skill 和工具，而不是一次放入全部能力。
3. **执行并观察结果**：调用工具处理数据，读取返回结果，发现缺项或错误后调整下一步。
4. **检查并交付**：核对异常、生成周报，将草稿保存到工作区，供你审阅。
5. **根据反馈继续**：你可以要求修改、补充资料，或明确授权后续发送。

这种“模型决定下一步 → 工具执行 → 结果反馈 → 继续判断”的循环称为 **Agentic Loop（智能体执行循环）**。它支持根据实际结果调整执行过程，不意味着每个任务都能自动成功。

“不要发送”限定了任务范围；实际部署还应通过外部账号最小权限和审批策略限制发送能力，并检查执行记录。自然语言要求不能替代系统级权限控制。

## 持续工作依靠哪些能力 {/* #它有什么特点 */}

| 能力 | 对工作的帮助 | 当前边界 |
| --- | --- | --- |
| **上下文工程（Context Engineering）** | 按需加载 Skills 和工具，结合上下文压缩，为长任务保留目标、约束、进度和关键结果 | 压缩不等于无限上下文，也不能保证无损保留每个细节；关键材料应保存为文件 |
| **长期记忆（Long-term Memory）** | 默认开启，在同一用户的多个会话间复用稳定偏好、已确认决策和背景，并结合来源证据核对 | 不等于保存所有聊天，也不能代替实时查询或新的操作授权 |
| **可恢复的长任务（Resumable Tasks）** | 结合会话状态、恢复快照和工作产物，在等待或中断后接续任务 | 恢复不保证每次外部操作恰好执行一次；结果不确定时需要先核验 |
| **智能体团队与多智能体编排（Agent Teams / Multi-agent Orchestration）** | 通过专用经理、岗位模板、成员会话树和经理委托组织分工，使用共享资料目录汇集成果 | 需要核对具体回复和产物；派发成功不等于任务完成，也不自动获得跨用户访问权限 |
| **工具调用与开放协议（Tool Calling / MCP / A2A）** | 连接工具、外部系统和远端 Agent，用 Skills 组织可复用的方法 | MCP 提供工具接入；当前 A2A 是客户端能力；可用范围受配置、版本和授权限制 |
| **人工审批与可观测性（Human-in-the-loop / Observability）** | 在需要时等待人工确认，通过状态、消息、工具结果和文件检查过程 | 审批依赖具体工具和策略覆盖，不是不可绕过的全局保证；执行记录也不等于完整评测平台 |

完成任务后，也可以让 xAgent 协助把稳定的做法整理、测试并改进为 Skill；需要固定角色、提示词和能力入口时，再配置专用 Agent。

## 多个智能体怎样分工 {/* #多个智能体怎样分工 */}

**Agent Teams（智能体团队）是多智能体编排的核心能力**，不是多用户账号管理。Server `v0.1.0` 已提供[虚拟团队](/docs/user-guide/virtual-teams)：专用经理、成员会话树、岗位模板复用、经理间委托、所有者指导和共享业务目录。个人用户也可以组织多个 Agent 为同一目标分工。

经理组织任务与成员协作，你可以通过所有者指导入口补充方向，并检查成员聊天、回复和共享产物。团队解散会整体归档并保留成员关系；恢复资料与继续执行是不同操作，恢复后仍需明确续跑。团队不自动获得跨用户资料或外部系统权限。

主 Agent 与子 Agent 分工仍是具体的执行机制之一：各会话独立维护上下文，通过消息和文件引用交换结果。团队编排与会话执行属于不同层次，团队成果仍应通过成员的实际回复和共享产物验收。

会话协作、工作编排（WorkGroup）和远端 A2A 解决不同问题：会话执行任务，WorkGroup 保存角色与通信关系等编排配置，A2A 客户端连接外部 Agent 并跟踪远端任务。发布配置、提交消息和完成任务是不同状态。详见[多 Agent 协作](/docs/guides/multi-agent-session-event-collaboration)和[远端 A2A](/docs/user-guide/a2a)。

## 如何理解它的产品定位 {/* #和普通聊天助手有什么不同 */}

xAgent 的重点不是增加一个聊天窗口，而是把 AI Agent 完成持续性工作需要的能力组织起来：

- **对话是交互方式**：用户通过会话说明目标、补充信息和检查结果。
- **Agentic Loop 是执行方式**：模型结合工具结果决定下一步，而不是只输出一次回答。
- **Skills 与工具是能力组合**：Skills 说明怎么做，工具执行具体动作，MCP 等协议连接外部能力。
- **平台承接持续运行**：管理会话、文件、长任务、协作、审批与模型配置，支持个人和多用户使用。

其他 AI 产品也可能具备工具调用、记忆或多智能体能力。选择时应根据实际任务验证完成质量、接入方式、权限控制、部署要求和成本，而不是只比较“聊天”或“智能体”的标签。

## 它不负责什么 {/* #它不负责什么 */}

xAgent 不替代组织的账号体系、业务权限、备份和审计。外部系统能访问什么，仍由外部账号以及 AgentPlugin 或 MCP 的授权决定。自托管也不等于数据绝不外发；模型服务和外部工具会按实际配置接收相关任务数据。

它运行在服务端，不需要每台电脑都安装客户端。长期稳定运行建议使用 Debian Linux；macOS 是 xAgent 的主要开发环境，支持也很好。Windows 当前沙箱能力不足，无法为受控脚本执行提供同等安全、可控的保障，因此暂不建议作为部署环境。

## 几个常用 AI 术语 {/* #几个词用大白话解释 */}

| 名词 | 在 xAgent 中的含义 |
| --- | --- |
| Agent（智能体） | 理解目标、规划并调用工具，根据执行结果继续推进任务的主体 |
| Skill（技能） | 可复用的任务方法，说明何时使用、步骤、约束和质量要求 |
| Tool（工具） | Agent 可调用的具体操作，例如读取文件、查询数据或发送消息 |
| MCP（Model Context Protocol） | 连接外部工具与能力的协议，不等同于某个工具本身 |
| Context Engineering（上下文工程） | 为当前执行步骤组织相关指令、材料、历史和能力说明 |
| Memory（记忆） | 跨会话复用的稳定背景，与当前会话历史和上下文压缩分开管理 |
| Workspace（工作区） | 保存任务材料、中间文件和最终结果的空间 |
| AgentPlugin（连接插件） | xAgent 连接微信、Telegram、飞书、钉钉、数据库或 SSH 等系统的插件机制；浏览器由内置 Runtime 管理 |

管理员可以统一配置公共能力；有相应入口和权限的用户也可以配置个人 Skill、MCP 或插件。普通用户通常只需要说明目标、限制和交付要求。完整定义见[术语表](/docs/reference/glossary)。
