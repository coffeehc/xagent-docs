# 术语表

## 适用对象 {/* #适用对象 */}

本文适合所有 xAgent 文档作者和读者。

## 这是什么 {/* #这是什么 */}

术语表是 xAgent 文档的固定用词来源。优先使用 AI 领域常见术语，再说明它在 xAgent 中的具体含义和边界；产品专有名词用于对应界面、配置或实现，不替代通用概念。

xAgent 的产品定位是**面向持续工作的 Agentic 平台**。Agentic 能力是核心；私有化部署、多用户入口与统一配置是部署和管理层面的扩展。

## 核心 AI 术语 {/* #核心术语 */}

| 术语 | 固定含义 |
| --- | --- |
| Agent Harness（智能体运行体系） | 模型之外支持执行的运行机制，组织工具、上下文、记忆、进度恢复、协作与人工审阅；不是单个模型、提示词或认证标准 |
| Agent（智能体） | 理解目标、规划、调用工具，并根据执行结果继续推进任务的主体 |
| Agentic Loop（智能体执行循环） | 模型决定下一步、工具执行、结果反馈、模型继续判断的循环；不表示任务必然成功 |
| Tool Calling（工具调用） | Agent 通过工具接口执行具体操作，并读取结果作为下一步判断的依据 |
| Tool（工具） | Agent 可调用的具体能力，例如读取文件、查询数据或发送消息 |
| Skill（技能） | 可复用的任务方法、约束和工具使用指导；不等于一个工具，也不自动授予工具权限 |
| Context Engineering（上下文工程） | 为当前任务组织指令、材料、历史与能力说明；xAgent 包括按需加载 Skills 和工具，以及上下文压缩等机制 |
| Context Compaction（上下文压缩） | 压缩当前会话历史，保留目标、约束、进度和关键结果以便继续执行；不等于长期记忆、无限上下文或无损保存 |
| Agent Memory / Long-term Memory（长期记忆） | 在同一用户的多个会话间复用稳定偏好、已确认决策和背景的实验性能力；结合来源证据、时间与当前事实核对，不保存所有聊天 |
| Resumable Execution / Tasks（可恢复执行 / 任务） | 结合会话状态、恢复快照和工作产物，在等待或中断后继续任务；不保证外部操作恰好执行一次 |
| Multi-agent Collaboration（多智能体协作） | 多个独立 Agent 会话通过明确任务、消息和产物引用协作；包括主 Agent 与子 Agent 分工，不等于共享全部上下文或跨用户授权 |
| MCP（Model Context Protocol） | 连接外部工具和能力的协议；工具能否使用仍取决于连接、配置和授权 |
| A2A Client（Agent2Agent 客户端） | 在用户范围内连接远端 Agent、跟踪远端任务并接收结果；当前客户端能力不等于对外提供 A2A 服务端 |
| Human-in-the-loop（人工参与 / HITL） | 在任务中保留人工补充信息、审阅结果和审批动作的环节；具体审批覆盖范围取决于工具和策略 |
| Observability（可观测性） | 通过任务状态、消息、工具结果和产物检查执行过程；不等于完整的自动化评测平台 |
| BM25 检索 | 按词项相关性检索记忆与产物的能力；不能表述为向量检索或 GraphRAG |

## 产品与技术术语 {/* #产品与技术术语 */}

| 术语 | 固定含义 |
| --- | --- |
| Task（任务） | Agent 执行的目标单元 |
| SubAgent（子智能体） | 接受明确子任务、独立维护上下文并执行工作的 Agent 会话 |
| Session（会话） | 用户与 Agent 交互、执行任务和保留状态的上下文 |
| Workspace（工作区） | Agent 执行任务时使用的文件、上下文和中间产物空间 |
| AgentPlugin（连接插件） | 连接外部系统的插件服务、用户 Channel 和能力声明来源；`0.0.16.beta` 前称 Connector |
| ProcessSandbox | 执行不受信任进程的平台隔离边界，负责文件挂载、环境、进程树和资源限制 |
| Runtime Assets | 由 xAgent 独立安装和校验、以只读方式提供给 ProcessSandbox 的执行依赖 |
| Execution Lease | WorkspaceFileService 为一次进程执行提供的最小文件视图、重叠写入协调和文件变化提交能力 |
| 触发器 | 把未来时间或外部事件转换成 Session 任务的机制 |
| 虚拟团队 | Server 0.1.0 提供的专用经理、成员会话树、共享业务目录与整体归档能力 |
| WorkGroup（工作编排） | 已实现的智能体及通信关系编排配置，支持草稿与发布版本；实际任务由各 Session 执行 |
| 工作记录（Work Record） | 会话范围的主题记录、修订与增量，用于核对连续性与阶段证据 |
| Model Profile ID | 模型配置的稳定引用，区别于显示名和 Provider 的真实模型 ID |
| 投递回执 | 某个消息阶段已被接受的证据，本身不等于整个任务已经完成 |

## 什么时候使用 {/* #什么时候使用 */}

所有使用手册、技术参考和维护说明都应使用本文术语。普通用户页面先解释工作价值，再在首次出现时给出常用中文与英文名称；后续保持一致，不堆砌缩写。涉及界面操作时，保留实际 UI 名称。

## 基本用法 {/* #基本用法 */}

写文档时：

- 先写用户能完成什么，再解释对应的 Agentic 能力；不要用内部实现名词代替产品定位。
- 不随意创造同义词，也不为了使用热门术语而扩大能力范围。
- 不把规划能力写成已实现能力；明确标注实验性功能、版本差异和适用边界。
- 区分记忆、上下文压缩与资料检索；区分调用成功、消息投递与任务完成。
- 新增术语时同步本文、中英文对应页和相关概念文档。
- 普通用户页面优先解释“怎么用”，技术参考页再解释内部边界。
